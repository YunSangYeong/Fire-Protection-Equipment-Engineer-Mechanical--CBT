# Fire-Protection-Equipment-Engineer-Mechanical--CBT
소방설비기사(기계)

비공식 필기 학습 CBT. **현재는 자체 제작 200문항이며 목표 1,000문항보다 800문항 부족합니다. 공식 시험 규칙·현행 소방 법규 대조와 전문가 검수는 미완료입니다.**

전기기능사 표준의 실제 React/TypeScript/Vite 앱을 재사용했습니다. 스킬은 `YunSangYeong/electrician-cbt` 최신 main `76b990b8720adfa85c22a0a8f699b17094aa357b`의 **v1.4.0 전체 폴더**, 앱은 스킬이 고정한 `b9a682ccff1b460334b78d5bfad9375b7ec4fbb6`에서 가져왔습니다. 원본 저장소에는 쓰기·배포를 하지 않았습니다. 기존 AGENTS.md는 없었으며 표준 연결 지침을 새로 추가했습니다.

## 기능

- 대시보드, 실전 모의시험, 랜덤 문제풀이, 오답노트, 북마크, 과목별 통계, 문제은행 관리
- 실전: 과목별 무작위 20개·총 80개, 답안 변경·문항 번호 이동, 절대 종료 시각·새로고침 복원·만료 자동 제출, 별도 제출 확인, 과락 포함 결과·전체 해설·오답 재학습
- 랜덤: 과목 선택, 순회 중 ID 중복 방지, 즉시 채점·연속 정답·이어하기
- 두 모드 모두 답안 선택 후 Space로 다음 문제. 미응답·길게 누르기·수정키·IME·입력 요소·열린 메뉴·대화상자 보호. 마지막 시험 문항에서 자동 제출하지 않음
- 학습 기준/연도 선택 UI 없음. 상단 상시 면책 배너 없음. 비공식 표시는 사이드바/푸터, 규칙·출처 한계는 문제은행 관리와 문서에 표시
- 작은 높이·가로 화면에서 메뉴 자체 위/아래 스크롤. `100vh`/`100dvh`, overflow, 자식 높이 보존, overscroll containment
- JSON/CSV 양식·가져오기·중복 제거·검증 대기·근거 입력 후 로컬 승인·검색·페이지·내보내기
- localStorage namespace `fire-mechanical-cbt:v1`. 최근 응답 5,000개·시험 30회 보관. 손상 원본 보존·저장 실패 경고. 기록 백업 내보내기와 확인 후 초기화. **백업 파일의 UI 복원 기능은 없습니다.** 로컬 가져오기는 공용 Git 문제은행을 변경하지 않습니다.

## 시험 규칙과 확인 상태

설정은 `src/qualification.ts`에 있습니다. 아래는 일반적으로 알려진 필기 구성을 적용한 **학습용 잠정값**이며 공식 확인 완료라는 뜻이 아닙니다.

| 항목 | 잠정 적용값 |
| --- | --- |
| 과목 | 소방원론 / 소방유체역학 / 소방관계법규 / 소방기계시설의 구조 및 원리 |
| 문항 | 과목별 20개, 총 80개, 객관식 4지선다 |
| 시간 | 총 120분 |
| 배점 | 과목별 100점(문항당 5점), 전체는 4과목 평균(문항당 평균 기여 1.25점) |
| 합격 | 평균 60점 이상이며 모든 과목 40점 이상 |
| 미응답 | 오답 처리. 화면 점수 반올림 전 원값으로 합격 판정 |

공식 확인 시도: [Q-Net 종목 상세](https://www.q-net.or.kr/crf005.do?id=crf00503&jmCd=1900), 2026-10-25, `curl` 결과 `CONNECT tunnel failed, response 403`(종료 56). 본문을 읽지 못했습니다. 출제기준 파일·시험시간·과목·판정 규칙의 공식 원문 대조는 미완료입니다. 특정 법령 조문·법정 수치·현행 기술기준을 확인했다고 주장하지 않습니다. 실기 시험은 구현 대상이 아닙니다.

## 실제 문제은행과 이용 조건

| 과목 | 개념형 | 계산 조건 변형 | 합계 |
| --- | ---: | ---: | ---: |
| 소방원론 | 20 | 0 | 20 |
| 소방유체역학 | 20 | 60 | 80 |
| 소방관계법규 | 20 | 0 | 20 |
| 소방기계시설의 구조 및 원리 | 20 | 60 | 80 |
| 합계 | 80 | 120 | 200 |

- 원문 기출 0, 복원 0, 자체 제작 200. 확인되지 않은 연도·회차는 모두 null. 외부 기출 재배포 허락은 확보하지 않았고 민간 문제를 복제하지 않았습니다.
- 기본 JSON 내부 검수 상태 `reviewed` 200, `pending` 0. 이는 **AI 내부 검토**이며 전문가 검수 완료 200이라는 뜻이 아닙니다. 사용자 로컬 등록분은 집계에서 제외합니다.
- 계산 변형은 **6개 유형 × 각 20조건 = 120문항**입니다. 정수압·연속방정식·수동력·방수량·가정된 혼합비·이상 노즐 속도입니다. 120개의 독립 개념이나 기출이 아닙니다.
- 법규 20개는 법령 위계·시행일·경과조치·용어·범위·법규 독해의 기초입니다. **소방관계법규 전체 내용이나 현행 의무·설치 수치를 다루는 은행이 아닙니다.** 다른 과목도 기초 위주로 출제범위·난이도 재현을 보장하지 않습니다.
- 원고/생성: `scripts/generate_bank.py`. 데이터: `src/data/questions-main.json`. 고정 ID·순서·선택지 순환으로 결정적으로 생성합니다. 정답·해설은 AI 일반 지식과 표시한 기초 공식에 근거하며 읽지 않은 교재·공식 문서를 인용하지 않습니다. 문항 sourceUrl은 작성 저장소 위치이며 외부 정답 증빙이 아닙니다.
- ID·NFKC/공백 정규화 본문·보기 순서 무시 fingerprint 중복 0. 내부 의미 검토에서 정수압과 압력수두의 같은 식을 별도 유형으로 세지 않도록 후자를 이상 노즐 속도 유형으로 교체했습니다. 의미상 유사한 기초 개념은 존재하며 독립 전문가 중복 검토는 미완료입니다.
- 계산형 120개는 생성기 Python Decimal과 독립된 TypeScript SI 단위 공식으로 재계산하고 정답 번호·유일한 동치 보기·단위를 검사했습니다. 계산 통과가 현행 법규 대조나 전문가 해설 검수를 대신하지 않습니다.
- 자체 문항·해설·양식: **CC BY 4.0**, 이 저장소와 문항 ID를 표시하고 변경 사실을 명시하세요. 코드: 원본 MIT 고지 보존. 제3자 등록 자료는 별도 권한 확인이 필요합니다.
- **최종 1,000문항 인수 기준 미충족: 실제 200, 부족 800.** 검증되지 않은 대량 생성이나 반복 수치 변형으로 목표를 채우지 않았습니다. 부족분의 원문 권리 확인·다양한 문항 확보·별도 검수가 필요합니다.

## 로컬 개발과 검증

Node.js 24.19.0, npm 11.9.0, Python 3.12.14로 검증했습니다. 각 작업은 기존 격리 체크아웃에서 수행하며 별도 worktree를 만들 필요가 없습니다.

```sh
npm ci
npm run dev -- --port 5173 --strictPort
npm test
npm run build
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

시스템 Chromium이 없는 환경은 `npx playwright install chromium` 후 `npm run test:e2e`를 사용합니다. CI는 `npx playwright install --with-deps chromium`을 사용합니다. 기본 데이터 재생성은 `python3 scripts/generate_bank.py`이며 바이트 동일성 검사가 있습니다. 서버·DB·비밀키는 필요하지 않습니다.

실행 결과와 한계는 [검증 기록](docs/validation.md), 배포 중단 상태는 [배포 기록](docs/deployment.md)에 기록합니다.

## GitHub 반영과 Pages

사용자가 구현부터 배포까지 요청했습니다. `.github/workflows/pages.yml`은 **main push → validate(단위·브라우저·빌드) 성공 → Pages 배포**, PR은 검증만 수행하도록 준비했습니다. Pages base는 `/Fire-Protection-Equipment-Engineer-Mechanical--CBT/`입니다.

배포 사전 확인의 첫 GitHub API 호출이 `Forbidden`으로 실패하여 요청 정책대로 중단했습니다. **main 푸시·Actions 실행·재시도·대체 배포는 하지 않았습니다.** 코드 보존용 비배포 브랜치 `cbt-implementation`을 사용하며 이 브랜치 push는 workflow를 시작하지 않습니다. CI·Pages 배포 성공과 공개 화면은 확인되지 않았습니다.
